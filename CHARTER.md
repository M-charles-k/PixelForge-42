# Group Project Working Rules

## 1. Communication
- All project updates go in the group chat.
- If you're stuck or behind schedule, say so early. Don't wait until the deadline to flag a problem.
- Respond to group messages within 24 hours where possible.

## 2. Roles & Ownership
- Each member owns their assigned part (e.g. wireframes, backend, documentation) and is responsible for delivering it on time.
- If you can't complete your part, tell the group immediately so someone can help or the deadline can be adjusted — don't go silent.

## 3. GitHub Workflow
- All work is committed to the shared repository.
- Use clear commit messages (e.g. "Add wireframe for Order Lookup and Stock Checker", not "update").
- Use GitHub Issues (or the Project board) to track tasks — mark your task "In Progress" when you start and "Done" when finished.

## 4. Deadlines
- Internal deadlines are set at least 2 days before the actual submission deadline, to leave room for review and fixes.
- Missing an internal deadline without communicating counts against that member's contribution.

## 5. File & Naming Standards
- Name files clearly and consistently (e.g. `wireframe.pdf`, not `Untitled(3).pdf`).
- Keep design/documentation files in their designated folder (e.g. `/docs`, `/design`) — don't scatter them across the repo.

## 6. Review & Quality
- Before marking a task "Done," at least one other group member should review it.
- Give feedback constructively and promptly — don't let reviews sit unread.

## 7. Final Submission
- One member is designated to do the final compile/check before submission (confirm this person in advance).
- Double-check all files are uploaded to GitHub and any required document (e.g. Word/PDF report) is finalized before the deadline.
